# BLAS flyoff: macOS arm64

Bare metal, the Apple M6 Mac mini. Part of the
[BLAS flyoff](results-flyoff.md).

- **Machine:** Apple M6 Mac mini, macOS 27.0.1 (26A434). The clock probe
  read 3.7 to 4.1 GHz as each run started, from a cold start, and 4.78 to
  4.79 GHz from level 2 on; the threaded runs (level 3 alone) started at
  3.5 to 3.9 and ended at 4.47.
- **Build:** Zig 0.18.0-dev.751+069480a1a, ReleaseFast, CPU model
  `apple_m1`, `-Dblas-cores=all`; rstd detects `vortexm4`. rstd at
  `review` `6d66239`, with the bench's `--rstd-accelerate` option. No
  `-Dopenblas`, so no `ob .S` column.
- **rstd:** by default its routines run Accelerate wherever
  `apple_accel.zig` routes them, so `rstd` mostly tracks `accelerate`.
  [Own kernels](#own-kernels-level-1) is the same bench with
  `--rstd-accelerate=0`: rstd's own kernels, as before the routing landed.
- **OpenBLAS:** 0.3.33 from nixpkgs at `5adc5083`, `openblasCompat`, the
  same store path as plain `openblas` here
  (`/nix/store/s2xzgzc6dbj1bgz5qf9331zha3g0w1w3-openblas-0.3.33`), as in
  [`results-m6-libraries.md`](results-m6-libraries.md). `OpenBLAS 0.3.33
  DYNAMIC_ARCH NO_AFFINITY neoversen1 MAX_THREADS=64`.
- **Accelerate:** the system framework, through its `$NEWLAPACK` entries,
  `BLASSetThreading` single-threaded.
- **BLIS:** none: nixpkgs builds BLIS for x86_64-linux only
  (`meta.platforms`), so its cache has no Darwin build.
- **Threads:** one each; default threading: OpenBLAS 12, Accelerate
  multi-threaded; rstd one thread either way.
- **When:** 2026-10-29, 01:35 to 02:29 CDT, under the timing rule below;
  each run's load and busiest processes are under
  [run conditions](#run-conditions).

Columns as [`results-flyoff.md`](results-flyoff.md#reading-the-tables) has them.

## Timing rule

The user's rule of 2026-10-29. macOS cannot be quieted further: its
indexing daemons (`mediaanalysisd` at about two cores, `textunderstandingd`,
`corespotlightd`, `modelcatalogd`, `spotlightknowledged`) are SIP-protected.

- A run starts when no `qemu-system` process runs on the Mac and the
  1-minute load is under 10. `uptime` and the top 8 processes are recorded
  before and after it. Runs go one after another, never beside the Linux VM.
- Before each run, `taskpolicy -b` puts the logged-in user's busy daemons
  in the background; it was accepted every time.
- Each invocation runs twice. A row counts when two runs agree within 3% on
  every rate; else its section runs again, up to 3 more times, and a row
  still apart would be marked noisy. A row shows the better rate of its
  agreeing pair. Level 1 took 4 runs with Accelerate and 3 without,
  default threading 4. No row is noisy.

## Accelerate routing

Against rstd's own kernels, routing is faster in 162 of 228 rows, within
3% in 29, and slower in 37:

- **Faster:** all of `gemm` (6.4 to 15.8 times), `gemv` (1.45 to 54), contiguous `dot`
  except `sdot`, `asum`, and the contiguous `axpy`, `scal`, `copy`, `swap`
  and `rot` that fit in cache (up to 8.4).
- **Slower:** every `nrm2`, as Accelerate's is the slower one (`dznrm2` at
  0.06 to 0.21, `dnrm2` 0.25 to 0.48, `snrm2` and `scnrm2` 0.53 to 0.92);
  contiguous `sdot`, at 0.41 to 0.50, as `cblas_dsdot` (rstd's `f64`
  sum) runs 40 to 48 GB/s where rstd's kernel runs 97 to 99; strided
  `copy` (0.52), and strided complex `dot`, `axpy`, `rot` and `swap` (0.77
  to 0.96).
